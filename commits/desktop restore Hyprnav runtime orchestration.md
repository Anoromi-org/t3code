# Desktop restore Hyprnav runtime orchestration

Restore the Wayland-native Electron bridge for scoped Hyprnav environments, atomic slot synchronization, locking, naming, workspace targets, worktree terminals, favorite editors, shell commands, no-op bindings, and external Corkdiff commands.

Worktree terminals launch or focus per-worktree Ghostty sessions through Hyprnav. The helper is packed as its own self-contained `ghostty-worktree-entry.cjs` bundle and staged into packaged desktop builds as the `ghostty-worktree.cjs` extra resource. Runtime path resolution supports both electron-builder resources and the Nix app-root layout, where the helper runs from `apps/desktop/dist-electron`. Unavailable runtime dependencies return explicit status results instead of rolling back saved configuration.

The preload exposes worktree terminals, Hyprnav sync/lock, and external Corkdiff behind one `canUseHyprlandIntegrations` gate (Linux under Hyprland). IPC methods sit next to the Corkdiff entries in upstream's handler and channel registry.

`ThreadRouteView` mounts the renderer orchestrator for server thread targets only. The orchestrator publishes and locks the current thread environment when the thread belongs to the runtime primary environment, retries transient failures and partially applied scopes without letting superseded threads relock themselves, and retains removed-slot/name cleanup across attempted, acknowledged, and restarted renderer state. A semantic request fingerprint keeps projection object churn from restarting publication. It includes the preferred editor only when a favorite-editor binding exists, so switching editors republishes that slot. Desktop sync reports the exact scopes it applied, so stale-worktree recovery acknowledges the project fallback without discarding pending worktree or thread cleanup. One target's failure, a missing editor, or failed Corkdiff credential resolution drops only the affected bindings. Persisted publication history contains only slot numbers and name-presence flags, never commands or credentials. It refreshes Corkdiff websocket tickets before expiry through the plugin-redacted `token` query parameter. Hyprnav-launched Corkdiff listens on a stable per-thread Neovim socket, so refreshed connections update the running process, identity-matched sockets whose probe fails to connect are recovered before future launches, and a probe timeout leaves a slow live owner's socket in place. Browser, remote threads, and desktop platforms without the optional Hyprnav bridge do not start the runtime.

## Reimplementation Sources

This intent reimplements fork commit `22fa6175e6`, which folds `58cd574b83`, `67d5567962`, `59a0721aac`, `8caf403e8c`, `4d4dacc149`, `7bf542c88e`, `282a2ed1fd`, `09bc332cd0`, `d20bd390e7`, `fdb52ac9d5`, and `e299e390b8`. The renderer runtime uses its latest fork version, including the runtime-behavior fixes from `3b795bc5bd`: primary-environment targeting, scope-retry, per-request failure isolation, and the shared publication history. Helpers that only settings-triggered publication uses (request-to-target and request-to-scope mapping) land with the web Hyprnav settings intent. The filesystem-election and external-`flock` recovery designs are provenance only. The implementation uses the final portable Linux abstract-socket mutex.
