# Server generate unique idempotent worktree branches

Generate the final worktree branch before creation, suffix occupied names, serialize competing requests per repository, and reuse successful creation on retries. Explicit existing branches and already selected worktrees remain reusable. Web and mobile request generation only when the server advertises `environment.capabilities.worktreeBranchGeneration`, with temporary branches for older servers.

- Contracts: `VcsCreateWorktreeInput.ensureUniqueRefName` / `idempotencyKey`, `prepareWorktree.generateBranch`, the environment capability. `buildGeneratedWorktreeBranchName` lives in `@t3tools/shared/git` (the first-turn rename of legacy temporary branches uses it too).
- `GitVcsDriverCore.createWorktree` holds a per-repository lock (keyed by the git common dir) only around the idempotency lookup, branch-name resolution and `git worktree add`. The key is remembered in repo config as `t3code-bootstrap.<sha256>.{branch,path,completed}` and reused only when completed, registered and still on its branch. A reused worktree still reports `onWorktreeClaimed` and runs the submodule step with the caller's options.
- `ws.ts` bootstrap: the server names unnamed worktrees from the first message (source-control writer model, falling back to the message text), passes the command id as the idempotency key, joins a retry that arrives while the original still runs (settled by the detached bootstrap fiber, not the possibly disconnected caller), and on a later retry reuses the remembered or already attached worktree without rerunning the setup script (live tracker snapshot or persisted setup activities). A retry for a thread that already has its worktree skips the setup card. Cancellation that removes the worktree forgets it, and a remembered or attached worktree path that no longer exists is not reused. "Start from origin" is ignored when an existing branch is checked out as is.
- Web: `/worktree <branch>` on a branch no checkout holds puts the worktree on that branch; `/branch` and the toolbar change only the source of a pending named worktree. Refs checked out in the project root are reused there instead of becoming a worktree base. Multi-model siblings ask the server to name each worktree; they never take a `/worktree <name>` target, since one branch cannot be checked out in several worktrees.
- Mobile: the outbox drain requests generation when supported; a worktree already selected in worktree mode is reused.
